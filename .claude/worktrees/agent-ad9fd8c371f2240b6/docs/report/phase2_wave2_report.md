## 1. 概览

Phase 2 Wave 2 的核心任务是对 SAM 项目中出现的两项严重架构问题进行根因诊断与修复:

- **维度坍缩 (Dimensionality Collapse):** 流形有效秩从初始值~27 下降到~6，引发对模型表示容量是否充足的担忧。
- **属性盲区 (Attribute Blindness):** 部分属性（如 OBJ 形状、MAT 材质）在 PCA 方差中几乎不可见，模型似乎"无视"了这些属性。

经过系统的对比实验和诊断，我们得出一个关键结论: **"维度坍缩"是一个误导性叙事**。有效秩 ~6-10 对于当前任务已经足够，真正的问题是**属性不平衡 (Attribute Imbalance)**——即部分强信号属性在有限的流形容量中占据了不成比例的资源，挤压了其他属性的表示空间。

Wave 2 完成了三项架构修复: SpectralNorm → Orthogonal 参数化、共享 MLP → 逐类别独立输出头、以及清理不可扩展的逐属性损失函数。同时完成了 Wave 3 的预备工作: VICReg + DecoderBottleneck 可扩展正则化机制的实现。

## 2. 根因分析

### 2.1 根因一: SpectralNorm 训练正反馈坍缩

**机制:** SpectralNorm 在训练过程中会追踪并约束权重矩阵的最大奇异值 (σ_max)。然而，训练梯度会放大对任务有用的方向 → 该方向的奇异值被梯度推动增大 → SpectralNorm 将该奇异值归一化为 1，从而压缩所有其他方向 → 有效秩从 27 下降到 6 → 进一步加剧梯度对少数方向的依赖，形成正反馈循环。

**数据验证:**
- P3 模型 (MLP+SpectralNorm, 30 epoch): 有效秩 = 5.99, D90 = 4
- 前 4 个 PCA 奇异值占比: 0.299, 0.258, 0.220, 0.189 — 之后的奇异值急剧归零 (第7个起 <1e-4)
- 这意味着 256 维流形中只有约 4-6 个维度携带有效信息，其余维度坍缩为噪声

**修复:** 替换为 `nn.utils.parametrizations.orthogonal`，强制 W^T W = I（所有奇异值 = 1），只做纯旋转变换，彻底阻断坍缩机制。

### 2.2 根因二: 共享 MLP 跨类别属性侵占

**机制:** 旧架构中所有类别共享同一个 MLP (384→512→256)。由于颜色 (COL) 的信号强度显著高于物体 (OBJ) 和材质 (MAT)，MLP 的参数被优化为优先编码颜色信息，导致弱信号属性在共享表示空间中被淹没。

**数据验证 (P3 流形健康):**
- COL 方差占比: 62.2%
- OBJ 方差占比: 4.0%（形状盲）
- MAT 方差占比: 0.3%（材质盲）
- OBJ-MAT 跨余弦: 0.985（几乎完全对齐，表示空间未区分这两个属性）
- OBJ-SIZE 跨余弦: 0.919（严重混淆）

**修复:** 每类别独立 MLP 输出头 + 直和 concat，架构级别阻止跨类别信号侵占。维度分配: OBJ=99, COL=67, SIZE=33, MAT=33, REL=24。

### 2.3 根因三: 缺乏全局信息保持机制

原始四损失训练 (L_align + L_rel + L_analogy + L_disentangle) 只关注跨模态对齐和关系一致性，没有对嵌入**保留所有属性信息**施加任何约束。当流形维度成为零和预算时，模型自然地只保留对降低对齐损失最有用的属性。

**修复路径:** Wave 3 中引入 VICReg + DecoderBottleneck，这两种机制都不需要显式的属性列表，可扩展到任意数量的属性。

## 3. 架构变更

### 3.1 `sam/manifold/projection.py`: SpectralNorm → Orthogonal

```python
# 旧 (P3):
self.proj = nn.utils.parametrizations.spectral_norm(nn.Linear(dim, dim))

# 新 (v4+):
self.proj = nn.utils.parametrizations.orthogonal(nn.Linear(dim, dim))
```

**效果:** 彻底阻止训练过程中的秩坍缩。所有奇异值恒为 1，每步训练梯度只做纯旋转，不改变表示空间的维度利用。

**代价:** 失去缩放自由度，所有尺度调节必须在编码器内部完成。但这一代价是可接受的——LayerNorm 在编码器内部提供了所需的规范化。

### 3.2 `sam/encoders/symbol.py`: 共享 MLP → 逐类别独立输出头

| 组件 | 旧 (共享 MLP) | 新 (直和头) |
|------|-------------|------------|
| 架构 | 单一 MLP 384→512→256 | 6 个独立 MLP 头 → concat |
| 参数 | ~1.5M | ~0.4M (减少 4 倍) |
| 维度分配 | 统一 256 维 | OBJ=99, COL=67, SIZE=33, MAT=33, REL=24, PAD 剩余 |
| 跨类别干扰 | 严重（COL 侵占所有空间）| 架构级阻止 |

每个类别头接受 64 维嵌入，经过两层线性 (expand→LayerNorm→ReLU→compress→LayerNorm)，输出到各自分配的子空间维度，最后通过 `torch.cat` 拼接为 256 维直和。

**效果:** 结构保证每个类别至少拥有自己的子空间，不会被其他类别的强信号侵蚀。

### 3.3 移除废弃文件

Wave 2 中彻底移除了以下无法扩展的逐属性损失文件:
- `sam/losses/color_contrastive.py`
- `sam/losses/symbol_color.py`
- `sam/losses/perturb.py`
- `sam/losses/dimensionality.py`

以及相应的诊断脚本:
- `scripts/diagnose_dimensionality.py`
- `scripts/validate_orthogonal_fix.py`
- `scripts/test_orthogonal_train.py`

### 3.4 新增: `sam/losses/vicreg.py` (Wave 3 预备)

VICReg 风格全局正则化 + DecoderBottleneck 属性重建:
- **VICRegLoss:** 方差正则化 (防止维度坍缩) + 协方差正则化 (解耦维度)
- **DecoderBottleneck:** 轻量解码器从嵌入重建所有属性（信息论保证）
- **ManifoldRegularizer:** 两者的组合模块

这些机制已集成到 trainer 中，为 Wave 3 的训练做好准备。

## 5. 属性平衡翻转问题

### 5.1 翻转现象

架构修复成功地改变了属性的主导地位，但并未解决根本的不平衡问题:

| 属性 | P3 (MLP+SN) | v6 (Heads+Ortho) |
|------|-------------|-------------------|
| OBJ 方差 | 4.0%（形状盲） | 57.3%（形状主导） |
| COL 方差 | 62.2%（颜色主导） | 0.02%（颜色盲） |
| SIZE 方差 | 13.4% | 42.5% |
| MAT 方差 | 0.3%（材质盲） | 0.02%（材质盲） |

**P3 → v6: 从"颜色盲"翻转为"形状盲"，但问题没有消失。** 旧模型中 COL 占据 62% 的方差压抑了所有其他属性；新模型中 OBJ 占据 57% 的方差 + SIZE 占据 43%，COL 被压缩到 0.02%。MAT 在任何架构中都无法获得足够的表示空间。

### 5.2 COL-MAT 完全对齐

v6 的跨类别余弦分析揭示了一个更严重的问题:
- **COL-MAT 跨余弦: 0.999** — 颜色和材质的表示方向几乎完全一致，模型完全未区分这两个属性

这说明直和架构虽然阻止了 OBJ/COL/SIZE 之间的侵占，但直和结构本身并不能保证**同一类别头输出内部的子维度被有效利用**。COL 头和 MAT 头的输出在流形上指向了几乎相同的方向。

### 5.3 根本原因

1. **L2 超球面的零和方差预算:** 投影到单位超球面 S^{255} 后，某个属性方差的增加必然导致其他属性方差的压缩。这是几何层面的约束，不是架构可以完全解决的。

2. **对齐损失不要求保留所有属性:** L_align + L_rel + L_analogy 只需要跨模态匹配度足够高，不需要嵌入保留所有属性的可解码信息。模型可以采用"只编码对对齐有用的属性"的捷径。

3. **直和头的维度分配是固定的，但训练没有机制确保各子空间被充分利用:** COL 头的 67 维和 MAT 头的 33 维可以指向相同的流形方向，从而浪费了 MAT 子空间的容量。

## 6. 修正路线图: Phase 2 Wave 3

### 6.1 核心目标

实现**可扩展的正则化**——在不依赖属性列表的前提下，确保所有属性信息被保留在流形嵌入中。

### 6.2 方案: VICReg + DecoderBottleneck

**为什么逐属性损失不可扩展:**
- 在真实场景中，属性可能有数百个，且存在嵌套子属性和跨域属性
- 为每个属性设计独立的对比/分类损失需要不断维护属性列表
- 连续属性（RGB 颜色、位置坐标）无法用对比损失有效处理

**VICReg (Variance-Invariance-Covariance Regularization):**
- 方差正则化: 惩罚维度标准差低于阈值 γ，防止任何维度坍缩为常数
- 协方差正则化: 惩罚协方差矩阵的非对角元素，促进维度间解耦
- **不需要知道属性列表**，在全局嵌入上操作

**DecoderBottleneck (解码器瓶颈):**
- 轻量 MLP 解码器从嵌入重建所有属性
- 信息论保障: 如果解码器能从 z 恢复所有属性，那么 z 必然包含了所有属性信息
- **可扩展到任意属性**: 只需添加新的预测头，无需修改损失函数逻辑

### 6.3 实现状态

两模块已在 `sam/losses/vicreg.py` 中实现并集成到 trainer:
- `VICRegLoss` — 方差 + 协方差正则化
- `DecoderBottleneck` — 属性重建解码器
- `ManifoldRegularizer` — 组合模块

Wave 3 将在 v6 基线基础上，通过 VICReg + Decoder 启动 v7 训练，并对 v6 vs v7 进行全面的属性平衡评估。

## 7. 关键洞察

### 洞察 1: "维度坍缩"叙事是错误的

v6 (有效秩=6.2) 和 P3 (有效秩=6.0) 几乎相同的有效秩，但 v6 的 E1 准确率是 P3 的 3.2 倍。有效秩测量的是 PCA 谱的扩散程度，并不直接对应信息容量。当我们说"有效秩=6"时，我们只说了 256 维嵌入中只有约 6 个较大奇异值方向，但我们**没有测量这些方向上编码了多少信息**。

### 洞察 2: MAT 信息被编码在细微角度差异中

尽管 MAT 在 PCA 方差中仅占 0.2%（v5b），但其线性分类准确率达到 43.2%（随机基线 25%）。信息确实存在于流形中，但不是以主成分方向的形式——它是以不同维度上的细微协同差异编码的。

**PCA 方差 ≠ 信息含量。** PCA 测量的是统计方差的主方向，不测量可解码信息。一个属性可以在 PCA 中不可见但在分类器中完全可解码。

### 洞察 3: 架构修复翻转了主导属性但不解决根本问题

从 P3 (COL 主导) 到 v6 (OBJ 主导)，属性平衡问题从"颜色盲"翻转为"形状盲"。这证实了零和方差预算的几何约束: 在单位超球面上，一个属性的增益必然是另一个属性的损失。

### 洞察 4: 逐属性损失不可扩展

为每个属性设计独立的对比损失或分类损失，在只有 4 个属性的 toy dataset 上尚可管理，但在真实场景中无法扩展到数百个属性。Wave 2 清理了所有逐属性损失代码，为 Wave 3 的通用正则化铺平道路。

### 洞察 5: 直和架构提供了分离但未保证利用

逐类别输出头保证了每个类别拥有专用子空间，但不能保证这些子空间被有效利用。COL 和 MAT 的跨余弦为 0.999 说明两个头的输出几乎完全对齐——它们在流形上"写"了相同的信息。

### 洞察 6: 架构修复 + 正则化才是完整方案

单靠架构修复（Orthogonal + 直和头）只能防止最严重的坍缩和侵占，不能解决属性平衡问题。单靠正则化（VICReg + Decoder）在错误的架构下也会失效。两者必须协同工作: 架构提供分离的基础设施，正则化确保基础设施被充分利用。
